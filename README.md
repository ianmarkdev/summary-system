# Issue Intake and Smart Summary System

A Laravel 12 application that lets support and operations teams submit, triage, and track issues with AI-generated summaries and suggested next actions.

---

## Why these technology choices?

| Choice | Rationale |
|---|---|
| **Laravel 12** | Mature, convention-driven PHP framework; clean DI container, Eloquent ORM, and form-request validation map naturally onto the requirements. |
| **MySQL** | Fully relational database with strong production credentials. Chosen for its widespread availability, robust indexing (status/priority/category/escalated), and native support in XAMPP/Laravel. Connection details live in `.env` — switching to PostgreSQL is a one-line change. |
| **No extra Composer packages** | AI integration uses Laravel's built-in `Http` facade (Guzzle wrapper) for the Anthropic API call. No SDK dependency to install — the fallback path requires nothing external at all. |

---

## Features

- **Create / list / view / update** issues via a web UI and a JSON REST API.
- **Filtering** by `status`, `priority`, `category`, and `escalated` flag on both UI and API.
- **Validation** — incomplete or invalid requests are rejected with field-level error messages.
- **Smart summary** — each issue gets a short one-sentence summary and a suggested next action, generated by:
  1. **Claude API** (`claude-3-5-haiku`) when `ANTHROPIC_API_KEY` is set, or
  2. **Rules-based fallback** — deterministic, category/priority-aware text that works with no external calls.
- **Escalation logic** — an issue is automatically flagged (`escalated = true`) when:
  - Priority is `critical`, OR
  - Priority is `high` AND status is `open` AND the issue has been open for more than 24 hours.
- **Soft deletes** — records are never permanently removed.

## Quick start

```bash
# 1. Install PHP dependencies
composer install

# 2. Copy environment file and generate app key
cp .env.example .env
php artisan key:generate

# 3. Create the MySQL database (run once)
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS laravel_assessment CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"

# 4. Set your credentials in .env if needed
#    DB_USERNAME=root
#    DB_PASSWORD=your_password

# 5. Run migrations
php artisan migrate

# 6. (Optional) Seed 10 realistic demo issues
php artisan db:seed

# 7. Start the development server
php artisan serve
```

Open http://localhost:8000 — you will be redirected to the issue list.

### Enable Claude-powered summaries

Add your key to `.env`:

```
ANTHROPIC_API_KEY=sk-ant-...
```

Summaries are re-generated whenever a ticket's title, description, priority, or category changes.
If the API call fails (network error, quota, etc.) the system falls back to the rules-based generator automatically.

## REST API

All API routes are prefixed with `/api`. Responses are JSON.

### List issues

```
GET /api/issues
```

Query parameters (all optional):

| Parameter | Values |
|---|---|
| `status` | `open` · `in_progress` · `resolved` · `closed` |
| `priority` | `low` · `medium` · `high` · `critical` |
| `category` | `bug` · `feature` · `infrastructure` · `security` · `other` |
| `escalated` | `1` to filter escalated issues only |
| `per_page` | integer, default `20` |

### Create issue

```
POST /api/issues
Content-Type: application/json

{
  "title":       "Checkout button broken in Safari",
  "description": "The checkout button on the cart page does not respond to click events in Safari 17.x. The issue is not reproducible in Chrome or Firefox.",
  "priority":    "high",
  "category":    "bug"
}
```

Returns `201` with the full issue object (including generated `summary` and `next_action`).

### View single issue

```
GET /api/issues/{id}
```

### Update issue

```
PATCH /api/issues/{id}
Content-Type: application/json

{
  "status": "in_progress"
}
```

Only the fields you send are updated. Sending `title`, `description`, `priority`, or `category` triggers summary regeneration.

### Validation errors

Invalid requests return `422 Unprocessable Entity`:

```json
{
  "message": "The title field must be at least 5 characters.",
  "errors": {
    "title": ["The title field must be at least 5 characters."]
  }
}
```

## Business rules

| Rule | Implementation |
|---|---|
| `critical` issues are always escalated on creation | `Issue::needsEscalation()` → `Issue::escalate()` |
| `high` + `open` + age > 24 h triggers escalation | Same — checked on create and update |
| Escalation is idempotent | `escalate()` checks `$this->escalated` before writing |
| Summary source is recorded | `summary_source` column: `claude_api` or `rules_based` |
| Soft deletes | `SoftDeletes` trait — issues are never hard-deleted |
